# Insightra 架构与当前能力

## 当前运行结构

Vite + TypeScript + Svelte 前端，通过 `/api` 代理访问本机 FastAPI。
Python 3.12 虚拟环境位于 `.venv`，依赖锁定于 `backend/requirements.txt`。
SQLite 存放于 `data/insightra.sqlite3`，启动时使用 `PRAGMA user_version` 迁移，目前版本 2。

后端模块：

- `settings.py`：允许列表中的本地环境变量，掩码摘要、原子写入。
- `providers.py`：Tushare HTTPS 请求、超时、状态分类和错误脱敏。
- `routes.py`：配置、连接检验、行情缓存、文档与分块接口。
- `main.py`：生命周期、数据库迁移、本地 Origin / Host 检查、统一输入错误处理。
- `workspaces.py`：研究项目草稿、数据集目录、家庭布局保存与几何校验。
- `datasets.py`：结构化数据集导入、类型/引用校验、版本冲突保护和导出。
- `market_sources.py`：Tushare 市场/指数适配器、后台同步进度、单位归一化与只读数据集发布。
- `widget_boards.py`：小组件声明与兼容检查、数据绑定、看板版本及可复用编组模板。

前端模块：

- `App.svelte`：应用外壳、导航、主题、研究上下文。
- `pages/`：领域页面；`lib/TimeSeries.svelte`：响应式时序与数据表；`lib/api.ts`：请求与错误处理。
- `SupplyMap.svelte` / `network/NetworkAtlas.svelte`：全行业公司图、社群区域、结构指标、选择追踪、缩放与关系明细。
- `network/topology.ts` / `layout.worker.ts`：唯一公司关系、连通网络、社群和中介中心性分析；Worker 中计算静态布局。
- `DataManager.svelte` / `JsonTree.svelte`：结构化数据的表格、树与源码编辑。
- `Health.svelte`：长期趋势、睡眠节律与每日记录的示例日志。
- `MarketDashboard.svelte` / `lib/widgets/`：绑定数据的行情组件、组件库、编组和看板持久化。
- `MarketSources.svelte` / `LoadingSurface.svelte`：数据源接入 UI 与共享加载骨架。
- `ResearchDesk.svelte`：研究项目、数据集、实验记录及产业网络工作视图。
- `Observatory.svelte`：由市场、研究、知识与生活构成的连续概览。
- `Home.svelte` / `LiftedFloorPlan.svelte`：家庭布局、独立拖拽浮层、落点预览与提交；几何模型位于 `lib/home-layout.ts`。

## 凭证和数据边界

`.env` 是未加密本机文件，已排除版本控制。进程环境变量优先于 `.env`，页面不得覆盖进程环境提供的配置。
保存凭证不改写系统环境变量，不要求重启。Tushare 凭证变化后清除旧连接结果和行情缓存。
API 只返回配置是否存在、来源和固定掩码；不返回原值或最后几位。
上游地址固定，TLS 校验开启，不跟随重定向，不允许页面输入任意代理地址。
Binance 只预留凭证配置，不调用交易或账户 API。

本机 Host 和 Origin 检查用于限制浏览器跨站请求，不替代完整用户认证。当前绑定 `127.0.0.1`。
部署到远程或共享网络前需加入认证、授权、HTTPS 与更合适的凭证存储；当前不具备远程多用户支持。

## 文档与向量路线

当前正文按纯文本保存，内容 SHA-256 去重。最多 500,000 字符；前端单文件上限 1.5 MB。
分块按 700 字符窗口、600 字符步长，最后不足窗口的内容保留；以文档 ID 关联并级联删除。
SQL 查询使用参数绑定，全文检索当前用 LIKE，支持中文子串；没有声称实现语义检索。
后续加入 PDF 解析、OCR、结构化分块、embedding 模型、索引版本、近邻检索、降维与引用溯源。
真实向量生成需记录模型、维度、版本和源分块；原始文本保留，索引应可重建。

## 结构化数据与产业资料

`app_metadata` 的 `dataset:<id>` 保存标准化 JSON、原始格式、来源、版本和更新时间。
首次启动将 `demo/data/chain-map.js` 的 JSON 赋值体解析为 `industry-chain`，不执行 JavaScript；已有记录不会被启动过程覆盖，原文件不改写。
原始资料包含 258 家公司、20 个环节、685 条关系。证据标记与资料级来源链接沿用原始内容，尚未完成逐条原文核验。

`GET/POST /api/datasets` 列出/导入；`GET/PUT/DELETE /api/datasets/{id}` 读取/更新/删除；`GET /api/datasets/{id}/export` 导出。
支持 JSON、CSV、TSV、JSONL。CSV/TSV 使用标准解析器保留带引号、逗号、换行与前导零的文本；嵌套 JSON 可用树编辑。
单数据集上限 3 MB、嵌套上限 30 层；保留字段名称被拒绝。CSV/TSV 导出对象数组，嵌套值序列化为 JSON 文本。
更新必须携带 revision，数据库写事务中检查版本；过期版本返回 409。产业数据额外校验节点/环节 ID、关系端点、标签与路径方向；被图谱引用的产业集不可删除。
表格按每页 40 行呈现；离开编辑器时尝试把未保存草稿留在浏览器。保存后数据库为正式来源，图谱重新打开/刷新读取新版本。
数据集目前保留最新版本和版本号，不是全量历史版本仓库；不提供历史回滚。

## 专业研究路线

以研究任务为单位串联：假设 → 数据集快照 → 因子版本 → 验证运行 → 回测运行 → 模拟执行 → 实盘监控。
后续运行实体应包含输入数据时间范围、可用时间、代码版本、参数、输出产物与状态，避免只保存一张结果图。
回测前明确复权、交易日历、费用、滑点、停牌/涨跌停、样本选择、公司退市与成交规则。
训练与验证按时间隔离，保留样本外结果；实战执行通过单独能力边界接入。

这些是后续计算设计方向，不是已实现的研究引擎。当前研究项目名称、假设与笔记已可真实保存，数据集目录读取行情缓存，实验列表保留诚实的未执行状态。

## 布局与研究存储

家庭布局写入 `app_metadata` 的 `home_layout`；研究项目写入 `project:<uuid>`。当前不需要额外数据库迁移。
`GET/PUT /api/home/layout` 读取/保存布局，后端校验 ID 唯一、房间边界与重叠、家具归属及边界。
`GET/POST /api/research/projects` 列出/创建项目；`PUT/DELETE /api/research/projects/{id}` 更新/删除项目。
`GET /api/research/catalog` 列出实际行情缓存。缓存不是不可变实验快照。

布局使用米为单位，房间绝对坐标、家具房间内相对坐标；JSON 包含 rooms 与 furniture。
浏览器保存未完成布局草稿，正式保存以 SQLite 为准。矩形房间与 8 类家具为本版范围；不模拟真实传感器连接。

## 全行业地图和行情扩展边界

主视图保留全部 258 家公司，685 条原始产品关系合并为 684 条有向公司连接。无向结构分析进一步合并为 682 对唯一公司关系，形成 143 家和 115 家的两个连通网络。
社群不使用行业标签预设：先进行确定性的局部模块度优化，再合并仍能提高模块度的社群。当前资料产生 6 个社群；不是完整 Louvain 多层实现，不强制固定社群数量。
节点的连接广度统计不重复的关联公司；桥接中心性采用无向、无权 Brandes 算法，在各连通网络内归一化。当前两项指标使用全部证据记录，即使隐藏推断线也不更换口径。
Web Worker 中先布局社群，再布局公司，使用固定排序与确定性 D3 模拟。静态布局按拓扑复用，筛选和指标变化只影响视觉强调，不重新计算坐标。原始业务对象不直接传给 D3 修改。
全景、聚焦和排行共享选择。全景图中的社群区域只是背景，所有公司与有向连接仍独立存在。标签按视口与重要性避让，可通过缩放查看更多。

后续行情层单独维护“证券代码 / 时间 → 涨跌值”，不能把行情值加入布局输入。时间播放仅更新颜色、亮度和覆盖率；未获取或过期行情标灰，不能当作零涨跌。跨日期必须保持色阶口径一致，不按每帧重新归一化。
公司可能对应不同市场证券，需区分实体与证券、交易日历、复权口径及数据可用时间。供应关系的连接不等于价格相关性，未来相关性分析应作为单独层验证。本轮未实现行情播放、自动调仓或交易执行。

拖拽浮层的候选布局只保存在组件内；通过校验后才触发一次 onbegin/onchange。房间重叠、越界、实体家具重叠都会拒绝放置，地毯叠放除外。前后端共享相同几何约束含义，后端再次校验。

## 市场三层架构

**第一层：数据管理。** 两个适配器输出 `ashare.snapshot.v1` 和 `index.daily.v1`。前者通过交易日历选择最近完整交易日，并分页获取 `daily`、`stock_basic`、`daily_basic`；后者读取四个固定核心指数的最近 90 天日线。中国交易日期按 UTC+8 计算，18:00 前不选择当天，防止把盘后尚未完整更新的数据当成完整快照。

股票成交额从千元转换为元，总市值从万元转换为元。按证券代码合并、去重，记录缺失日线、分类和市值覆盖。市值权限不可用时保留成交额能力并明确警告；同步失败保留旧数据，不生成假行情。
数据集保存于既有 `dataset:<id>`，携带 schema、as_of、units、coverage、warnings、source_id、revision 和 read_only。这些源数据不能直接编辑，可复制为有明确本地来源的可编辑副本。后台同步通过 `/api/market-sources/{id}/sync` 发起，状态通过 `/api/market-sources` 读取。重启会把遗留 running 状态标记为中断。

**第二层：组件契约。** `/api/widgets/catalog` 声明组件的 schema、required_fields、optional_fields、slot 与兼容数据集。已有大盘云图、市场温度、细分行业、核心指数四种组件。兼容性同时检查口径与字段类型，股票快照要求单一交易日、唯一证券代码。`/api/widgets/resolve/{kind}/{id}` 可独立检验绑定。渲染组件只接收数据，绝不调用上游行情服务。

**第三层：看板编组。** `/api/boards/finance` 保存 revision 与 groups；每组包含标题和有唯一 ID 的组件实例。实例通过 sources（slot → dataset ID）绑定数据，并保存尺寸和面积指标。`/api/widget-groups` 保存可复用模板；整体添加时生成新的编组/组件 ID，保留来源绑定。看板使用乐观版本检查，数据集若被看板引用则不能直接删除。

看板共享按数据集 ID 缓存的读取结果，多个组件不会重复读取同一市场快照。初始加载占位、失败状态、刷新保留旧结果都由组件容器统一处理。大盘云图用 D3 层级矩形布局配合 Canvas 绘制，以免 5,000 多支股票创建大量 SVG 控件；行业可筛选、悬停查看公司，并提供辅助表格。

当前为收盘看板，不是实时行情或交易终端。细分行业采用当前 `stock_basic` 分类与成分等权涨跌均值，可能受个别新股的大幅变化影响；不是官方行业指数。同步保存最新快照，不构成完整历史行情仓库。来源失效或字段改变时组件显示缺失，不猜测替代数据。

数据文档：[股票基础信息](https://tushare.pro/document/2?doc_id=25)、[每日市值字段](https://tushare.pro/document/2?doc_id=32)、[指数日线](https://tushare.pro/document/2?doc_id=95)、[D3 Treemap](https://d3js.org/d3-hierarchy/treemap)。

## 组件刷新与展示配置

看板和成功数据使用页面内存及 sessionStorage 的标签页缓存，先呈现缓存、再后台校验。缓存不含凭证，存储配额不足时退回内存；缓存不是正式数据源，保存仍受后端 revision 校验。组件卸载时终止请求但保留显示缓存。

新增 `watchlist` 与 `market-movers`，均声明 `ashare.snapshot.v1`，额外要求 close 字段。自选列表通过 options.symbols 保存，最多 100 个代码；涨跌与成交排行由组件对已绑定数据排序。WidgetContent 共享普通卡片与 WidgetViewer 弹窗的渲染，避免复制数据读取逻辑。

WidgetInstance 保存 refresh_seconds（0/15/30/60/300/900/3600，默认 300）和 size（small/half/wide/full）；旧配置缺失周期时向后兼容。设置即时预览，保存看板和编组模板时一起持久化。

WidgetRefreshCoordinator 按组件 ID 维护独立计时、检查完成时间、成功数据与错误状态；按数据集 ID 合并并发请求。标签隐藏时暂停定时检查，返回时检查到期项；页面卸载时清除计时器并中止请求。绑定变化用序号防止旧请求覆盖新绑定。失败保留上次成功内容；读取成功后还需校验 schema、字段与交易日期契约。

此刷新重读本地已保存数据集，不调用上游接口；数据管理负责上游同步。检查时间与数据集 as_of 交易日期独立展示。Canvas 使用主题变量，监听主题变化重绘；full 尺寸独占栅格整行。

组件 options.height_units 可选 2/3/4，整卡高度为 180 × height_units px，独立于横向尺寸。缺省云图为 3，其他组件为 2；12px 栅格轨道分配卡片和底部间隔，内容内部滚动。云图采用固定 ±4% 红绿映射和深色中性底，24px 板块标题条预留在布局中，最后绘制标题和外边界，避免与个股混淆。

## 区间相关度分析

研究工作视图通过 `/api/research/correlation/stocks` 读取本地 A 股目录，`POST /api/research/correlation` 接收 2—20 个唯一证券代码和最多两年日期区间。`research_sources.py` 负责从 Tushare daily 读取日线并保存为只读 `stock.daily.v1` 数据集，同代码与区间复用已存数据；这些区间数据可在数据管理查看、导出。分析层只消费来源层提供的数据，不修改行情。

Pearson 以 daily.pct_chg 日涨跌幅为样本，在所有选择股票的共同交易日计算。没有价格填充或缺失补零；少于 5 天、零方差返回 null，并显示覆盖与样本警告。结果包含矩阵、共同日期、数据集版本；不支持因果推断、滚动相关或收益显著性检验。前端修改选股或日期后将旧结果标记为待重算，可点击单元格检查或导出 CSV。

A 股与指数适配器同步 open/high/low/pre_close/vol，vol 保持 Tushare 的“手”单位，amount 转为元。A 股同步从已保存看板中读取绑定该源的自选代码，为最多 100 只补充最近 180 自然日中的最多 60 条未复权日线到记录 history；读取失败明确记入覆盖警告。保存看板不会直接调用上游，新增自选代码需在数据管理同步后才具备历史。options.trend_days 允许 5/10/20/60，显示不足 N 条时保留实际覆盖，不拼接假行情。旧快照兼容展示，缺失字段显示 —。
